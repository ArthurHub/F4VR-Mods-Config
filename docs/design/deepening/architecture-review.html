Problem.
Devbench keeps its own copy of the panel's button, Reset and breadcrumb rules, and one has drifted: on an MCM mod with changes, devbench's runButton saves before a script (MCDevBench.cpp:795), the panel doesn't (Buttons.cpp:50 checks writesChangesAtOnce). So e2e tests check devbench's rules, not the player's.
Solution.
Finish what the row view started: a button view, a Reset value in the row view, and a crumbs list. The panel draws from them; devbench reports and presses from them, left with JSON and argument parsing.
  • Locality: one place per button rule
  • Leverage: e2e checks what the player sees
  • Button-help panel tests lose pixel presses
  • Devbench's copies deleted, not moved

Evidence: 35 of devbench's 47 commits also touched src/ui/. Devbench has no unit tests. Also unshared: Reset hidden when the control can't show the default (SettingRow.cpp:40), the Developer crumb over a report.
