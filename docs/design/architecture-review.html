Problem
The rules for what counts as a value of a type are spread over 9+ files. isSameValue is copied 4 times, the table-type test 4 times, and isChoice differs between files: the loader leaves Haptic out and the store includes it. cf.transform touched 17 src files.
Solution
A module per setting type that answers equality, canonical text, why a value is invalid, parsing from JSON and the default, and whether the value is kept as a table. The loader, both stores, the UI and devbench all ask it.
Wins
  • Locality: a new type is mostly one file
  • Delete 4 copies of isSameValue
  • isChoice drift can't recur
  • Each type's rules tested directly, once

Problem
The Store interface has 33 virtuals. 8 of them are lifecycle notifications, and FullPanel keeps their order by hand at 7 call sites. ConfigMenu also sends menu events to each concrete store itself.
Solution
A session module holds the current mod, page and pointed item, and tells the store once for each real change. FullPanel only says what is shown.
Wins
  • Locality: the order lives in one place
  • Tests use a recording store, not pixels
  • Store interface: one caller to learn it
Suspected bug, not confirmed and outside this review: replaceMod (FullPanel.cpp:242) calls open and readTexts but not showPage. After a live-copy reload, the client may never get PageShown for the page still on screen.

Checked and left alone

  • ClientCalls / NativeClients: a real seam with two adapters (native clients and test callbacks) and 750 lines of tests.
  • Game access through link-time doubles: a clean local-substitutable seam.
  • McmStore vs ConfigSpecStore: they genuinely behave differently (write at once vs pending changes). Only isSameValue is shared, and it moves in 01.
  • TomlFile, IniFile, ModFile, LiveCopies, TransformTuning: deep and well tested.
  • ConfigDefinition.h: wide, but plain data. ConfigSpecLoader: big, but it is schema reading and well tested.
  • Drawing.h: a grab bag of 49 functions, low risk.
Top recommendation

01: one module per setting type's value rules

It has the widest fan-out in the hot spots: cf.transform touched 17 files, and the rules are copied over 9+ files. It is purely in-process, so there is no seam to design. It already shows real drift (Haptic is a choice in the store but not in the loader), and every future setting type pays for it again. 02 comes next, because the suspected missing showPage after a reload is the kind of bug its locality would prevent.
