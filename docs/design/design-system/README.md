# Mods Config VR design system

The look of the menu: colors, type, sizes, the Dear ImGui style, and how each component and panel is drawn, with mocks. It is the source of the Design System artifact [Mods Config VR](https://claude.ai/artifact/MardL45HgwNbZ3ERXcjZfJ), which shows it as a page; this folder is the copy under source control. What the menu does is decided in the [design documents](../README.md), mostly in [UI and VR interaction](../ui-and-vr-interaction.md).

Start with [project/README.md](project/README.md): the rules, the mapping to `ImGuiStyle` and `ImGuiCol_`, and the index of the components.

## Files

`project/` is what is published to the artifact, as it is here:

- `README.md`: the rules of the design system.
- `tokens.json`: colors, type, spacing, sizes, borders and opacity, each with its use.
- `design-system.json`: the artifact's title and namespace, and a note on the last change.
- `components/bundle.css`: the classes the previews are drawn with.
- `components/<Name>/README.md`: how to draw the component, written by hand.
- `components/<Name>/preview.html`: the mock, generated by `tools/gen_previews.py`. `Cover` is the exception, written by hand.
- `fonts/Roboto-Medium.ttf`: the face the framework embeds, so the previews measure text as the game does.

The artifact also holds files its type writes when it is published: `api/`, `manifest.json` and `tokens.css`. They are not kept here.

`tools/` writes the generated files and checks a change before it is published. They need Python 3.11 or later; `render.py` and `measure.py` also need Playwright: `pip install playwright`, then `python -m playwright install chromium`.

- `gen_previews.py`: writes every `preview.html` but the cover's.
- `gen_theme.py`: writes [src/Theme.h](../../../src/Theme.h): every token as a C++ constant, the font scales, and `applyStyle`, which sets the `ImGuiStyle` fields and `ImGuiCol_` colors from the tables of the ImGui style section of `project/README.md`. A value in those tables that differs from its token, or an unknown token, stops it. `--check` only reports whether the header is out of date.
- `render.py [Name ...]`: compiles the tokens as the artifact does and saves a screenshot of each preview to `out/`, which git ignores.
- `measure.py [Name ...]`: the tree's height, whether its rows overflow, and any name cut short, from the pages `render.py` saved.
- `check_contrast.py`: the contrast table in the Color section of `project/README.md`, computed from `tokens.json` with a white world behind the glass.

## Changing it

1. Edit `tokens.json`, `bundle.css`, a README, or `tools/gen_previews.py`. Do not edit a `preview.html` other than the cover's, or `src/Theme.h`: the generators write over them.
2. Run `python tools/gen_previews.py` and `python tools/gen_theme.py`. pre-commit runs both on a commit that touches this folder or `src/Theme.h`, and fails the commit when either rewrites a file, so the generated files cannot fall behind.
3. Run `python tools/render.py <Name>` and look at `out/<Name>.png`. After a color change, run `python tools/check_contrast.py` and update the table in `project/README.md`.
4. Set `lastChange` in `design-system.json`: who, when, and a one-line note.
5. Publish it to the artifact, then commit.

A change that follows the design documents, or changes what they say, updates both in the same commit.

## Publishing

The artifact is updated in place from a Claude session that has the Artifact tool, such as Cowork. The publish names the artifact's URL, this folder as its `root`, `project/design-system.json` as its `file_path`, and every changed file under `project/` in `files`, each at its own path:

```json
{
  "url": "https://claude.ai/artifact/MardL45HgwNbZ3ERXcjZfJ",
  "root": "docs/design/design-system",
  "file_path": "docs/design/design-system/project/design-system.json",
  "files": {
    "project/components/ModTree/README.md": "project/components/ModTree/README.md",
    "project/components/ModTree/preview.html": "project/components/ModTree/preview.html"
  }
}
```

Files that are not listed keep their published version. The artifact refuses a publish over a file that was changed there since the session last read it, such as by an edit on the artifact's page. Read that file from the artifact, bring the change into this folder, and publish again, so that this folder stays the source.
