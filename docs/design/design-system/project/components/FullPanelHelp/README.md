# FullPanelHelp

The Help page: how the menu works, with the buttons the player's config has. Help (`?`) in the title bar shows it. Until it is first shown, Help is `? Help` in the `important` style ([FullPanel](../FullPanel/README.md)); showing it turns that off for good, and the menu's own settings can turn it on again.

**Provides:** the controls of the menu, each a name and a text, with the config's buttons and bindings in words.

- The crumbs are `MODS CONFIG FO4 » Help`: the first is pressed to go to the menu's front page, `Help` is where the player is. The Help button is not drawn selected: the crumb says where the player is.
- The tree keeps the selected mod and page: the Help page is shown in place of the page, and Back shows that page again. A row of the tree goes to its page, as from any page.
- A text item first, in `green-muted`: "The menu doesn't pause the game, so you can see changes in the world as you make them. The controls below reflect your current button configuration." Then four sections, each under a [SectionHeader](../SectionHeader/README.md) that does not fold: the page scrolls.
- Each line as the help line has a row's help: `Name: ` in `green`, the text in `green-muted`, in `t-body`, wrapped in the page's width with as many lines as it needs, `space-2` in from the page's edges. A line about a mark has the mark first, as its row draws it, in a 20 px column, `space-2` before the name.
- **Navigation**, with the shipped bindings:
  - Open / Close: "Long press both thumbsticks to open or close the menu. This also restores a minimized menu."
  - Point and select: "Only one hand controls the menu at a time, indicated by the mark at the end of its ray. Use that hand's trigger to select and thumbstick to scroll. These inputs are blocked from the game while pointing at the menu. Point away to use the trigger in-game without accidentally selecting anything."
  - Back: "Tap the grip on either hand while pointing at the menu to close a popup, cancel an edit, or go back one page. From Help, it returns to your previous page. From the front page, it closes the menu."
  - Move the menu: "Long press the grip on either hand while pointing at the menu to grab it. Move your hand to reposition it, then release."
  - Recenter: "Long press the thumbstick on the off hand to bring the menu in front of you. It also returns automatically if you move too far away."
  - Navigate pages: "The breadcrumbs in the title bar show your current location. Select any earlier page to jump back, or MODS CONFIG FO4 to return to the front page."
  - Minimize: "Select – in the title bar to hide the menu while inspecting changes in-game. Your current page and unsaved edits are preserved. Use Restore on your offhand wrist to bring it back and refresh its values, or Exit to close the menu (with a warning if you have unsaved changes)."
- **Changes**:
  - Save: "Changes wait until you select Save, which writes them, or Discard, which drops them. An MCM mod applies a change at once instead: see MCM below. Each mod's changes are separate, and you're asked first when leaving a mod or closing the menu with unsaved changes."
  - Undo one change, after the undo arrow in `amber`: "A changed value turns amber. Select the undo arrow after it to undo just that change. Discard, in the footer, undoes all of them."
  - Reset, after its mark: "Sets the mod's default value, like any other change. The help line shows the default."
  - Buttons: "A button that runs a mod's script asks you to save first, since the script reads the saved values. An MCM mod's buttons don't ask."
  - When a change takes effect: "A mod can show it with a mark after the setting's name:", then each mark of [TakesEffect](../TakesEffect/README.md) in `amber` with what it means. `Live`: "The mod applies the change as you make it, so you see it in the game before saving. It is still unsaved: Save keeps it, and Discard, or leaving without saving, restores the old value in the game too." `Save`: "The mod applies the change when you save." `Restart`: "The change applies after restarting the game. The front page reminds you until then." `No mark`, after the plain dot: "The mod doesn't say. MCM mods never do."
- **Marks**: `Amber value` in `amber`: "Changed, but not saved or kept yet."; `Red value` in `red` after the invalid mark: "Invalid. The help line explains why."; `Warning` after the warning mark: "Something to know about the current value. The help line explains it."; `Result` after the info mark: "A button returned a result. Point at its row to read it."; `Greyed row` at `opacity-disabled`: "Can't be changed. Point at it and the help line explains why."
- **MCM**, always there: MCM tag: "Shown after a mod's name in the list when its menu comes from MCM. Its changes work as described below."; Keep and Revert: "Changes apply as you make them, as in MCM's own menu, so you see them in the game and a button's script reads them. Keep accepts a change, and some mods only apply it then. Revert undoes it and runs the mod's script for it again."; Hotkeys: "A mod's hotkeys are shown but can't be edited here. Change them in MCM."; A mod that is greyed: "It can't be shown. Point at it to see why. The front page also lists it under Notices."
- A button or a binding is said from the player's config and handedness, shorter than the sentence of `InputBinding`: no time or threshold, and a chord of the same button on both hands as one press of both, "Long press both thumbsticks". Back and the move are buttons of the hand that points, so an A button is "the A or X button". A control the config turns off is left out.
- Nothing on the page is pressed. The footer is the selected mod's, with its status.
