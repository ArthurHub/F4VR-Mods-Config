# Unit tests: the test doubles and the panel tests

How the tests stand in for the game, and how they draw the panel. [CLAUDE.md](../../CLAUDE.md) has how to build and run them.

- `tests/TestSwf.h` builds an SWF file in memory, for a test of an image.
- `tests/TestGlobals.cpp` is the tests' own `getGlobal` and `setGlobal`, linked in place of the mod's `GameGlobals.cpp`: it has globals in a map in place of the game's, which a test fills with a `TestGlobals`, for a test of a store, of a condition and of a row that is pressed. The map is kept from test to test: a test that reads a global has a `TestGlobals`, which starts with none. `tests/TestProperties.cpp` is the tests' own `getProperty`, `setProperty`, `getOptionTexts` and `getFormText` in the same way, linked in place of the mod's `GameProperties.cpp`: a test fills its properties of scripts, the lists a choice reads its options from, and the names and descriptions of forms, with a `TestProperties`. A test of a ModSetting writes MCM's files in a folder of its own (`tests/TestFiles.h`, whose `ReadOnly` makes a file that cannot be written), MCM is not called in a test, which has no game. `tests/TestEvents.cpp` is the tests' own `mcm::sendEvent` and `mcm::sendPauseMenuEvents`, linked in place of the mod's `McmEvents.cpp`: it keeps the events the MCM store sends, which a test reads with a `TestEvents`. A source that sends an event needs no more than that. `tests/TestActions.cpp` is the tests' own `callFunction`, `runConsoleCommand`, `openWebLink` and `sendSavedMessage`, linked in place of the mod's `GameActions.cpp`: it keeps the functions a store calls, the console commands it runs and the F4SE messages of its Saves, which a test reads with a `TestActions`.
- `tests/FullPanelTests.cpp` checks what the panel does: what is selected, and what a press of the pointer on a row of the tree or on a breadcrumb selects. It draws the panel in frames of ImGui with no game and no renderer, which `tests/TestPanel.h` sets up as the framework's canvas does.
- `tests/FullPanelRenderTests.cpp` draws the panel the same way and saves it as images, to look at a change of the UI before it is tried in the headset. They check nothing and are not run by `ctest`: run `build/tests/Release/ModsConfigFO4VR_tests "[render]"`, and open the `.bmp` files in `build/tests/render/`. Add a case there for a new view or state of the panel. One case draws every page of the MCM showcase, and one every page of the config spec showcase. An image of a page is drawn from its pixels, as the game draws it from its texture, and a config spec's texture from the config spec showcase's DDS file of it.
- The end-to-end tests, which drive the running game through devbench, are Python, in [tests/e2e/](../../tests/e2e/README.md).
