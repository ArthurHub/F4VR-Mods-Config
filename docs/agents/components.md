# Components

The components of Mods Config FO4 VR, each with its files and its responsibility. [CLAUDE.md](../../CLAUDE.md) has the map of the source folders.

## What the menu has so far

So far the menu opens on its front page and lists the MCM mods that are installed. Its title bar has Help, which shows a page of the menu's controls with the player's buttons and stands out as `? Help` until the player first opens it, and Minimize and Close, as the wrist has. A mod that is selected shows its pages in the tree and their rows, and a config spec's page that is selected shows the pages under it, a level further in, with a breadcrumb for each. A row of a group is shown while the setting that controls the group is on. A switcher, a slider, a stepper and a dropdown that are kept in a global of the game, in a ModSetting or in a property of a script are edited, and so is a dropdown of the files of a folder, a stepper and a dropdown have the options of a FormList or of a property of a script, which are read in the game, a ModSetting has a Reset to the default of its mod, a button calls the function of a script, and so does a row whose value is set, with the value, a text input is typed on SteamVR's keyboard, a config spec's controller binding of a CommonFramework mod is shown as its icons and its sentence and is built from its parts in its editor, a haptic of a CommonFramework mod is a dropdown of the framework's patterns with each one's shape, and plays one on the hand that points, a color of a CommonFramework mod is its swatch and its numbers and is edited in its editor, with a picker and a slider for each channel, a transform of a CommonFramework mod is its numbers and is edited in its editor, with a slider for each axis of the parts its config spec turns on, an activation sphere of a CommonFramework mod is a section of its settings under a heading with the sphere's mark, a hotkey shows the key MCM has for it, read-only, and a control the menu does not have is its text and its type, with a help that says so. A config spec is read too, with its pages, its sections, which nest and fold, its settings, a read-only one among them, with how a number is shown, its choices, with their shared lists and their options from the game, its texts, spacers and images, its buttons, which call the function of a script or run a console command, with the text on their button, a style that makes one stand out, and an icon, and the conditions a row is shown and enabled by, and the warnings a setting and a button tell while theirs holds, and the mod ships its own config spec for its TOML. A config spec's values are read from its TOML and INI files, its globals and its properties of scripts as its mod is selected, and a change waits for a Save: the footer counts the unsaved changes, and has Save, which writes them into the files and then the game, or nothing where one cannot be written, and creates a file that is not there, and runs the action of each setting it wrote, and Discard, which takes them back. A value the player types that is no value of its setting is invalid, as one of a file is, and Save is disabled while one is. A `live` global or property is in the game as it is changed, until Discard puts it back. A setting's Reset sets the config spec's default, which waits for a Save too. A config spec's setting says when its change takes effect, which the help line has in a tag while it is pending, and is unknown, with no tag, where nothing says it, as for every MCM setting: the status after a Save that wrote one that takes effect after a restart says so, and so does the menu's front page until the game is restarted. A config spec's problems are in the log, and with the Developer tools of the menu's own settings on, its front page lists each config spec's errors and warnings, and a config spec's report reads it from a live copy of its spec.json, which is read again each time it is saved.
