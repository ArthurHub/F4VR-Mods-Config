# Components

Each component's files and responsibility, plus the traps the code doesn't make obvious. The code is the source of truth for behavior; the rules it implements are in [docs/design/](../design/README.md). [CLAUDE.md](../../CLAUDE.md) maps the source folders.

## The mod and the menu

| Component | Files | Responsibility |
| --- | --- | --- |
| **ModsConfigFO4** | [src/ModsConfigFO4.h](../../src/ModsConfigFO4.h) / [.cpp](../../src/ModsConfigFO4.cpp) | The `ModBase` subclass and F4SE entry points; the opening gesture, taken over from FRIK. |
| **Config** | [src/Config.h](../../src/Config.h) / [.cpp](../../src/Config.cpp) | The mod's TOML via `ConfigBase` (`g_config`), hot-reloaded. See [config-and-data.md](config-and-data.md). |
| **MenuController** | [src/menu/MenuController.h](../../src/menu/MenuController.h) / [.cpp](../../src/menu/MenuController.cpp) | The menu's game-free decisions, unit tested through its port (`tests/linked/menu/`); `g_modsConfig.menu()` is this. Owns the two stores, the native clients and the Full panel, and gives the panel its stores, quick launch entries, controls, handedness and Developer config. Tells the menu opening and closing to the MCM store and every native client in one place (`tellMenuEvent`), and runs the stores' per-frame work (`updateStores`), also while closed. Native API requests (`requestOpen`, `requestMinimize`, `requestRestore`, `requestReadAgain`), the panel's and the wrist's presses, and live-copy actions are queued and done in its frame update, in a fixed order: opening FRIK's config goes before a close asked in the same frame, which is left for the next frame, and a close before a minimize. Polls live copies every 0.5 s by the port's clock, also while closed, but not during Adjust in world. Tells the mod list its own mod, the category table, the choices from `Categories.toml` and the minimum to group from; registers the Categories rows' options on its own native client from `ModList::categoryOptions`, with its config spec store for the pending choices. Any Save its own client hears re-reads `Categories.toml`, which regroups. Its folders and plugin checks come in a `MenuSetup`, so a test gives its own. The mod's own client is a singleton with no unsubscribe, and its first handler for an id stays: only the controller that called `registerOwnOptions` puts handlers capturing itself there, the Categories rows' options in `setMods` included, so a short-lived test controller leaves nothing behind. A test of them uses the one controller that lives for the whole run (`lastingMenu`). |
| **MenuPort** | [src/menu/MenuPort.h](../../src/menu/MenuPort.h), [tests/linked/TestMenuPort.h](../../tests/linked/TestMenuPort.h) | The game side the controller asks: the panel in the world and the wrist buttons, Back, thumbstick, handedness, haptics, Adjust in world, image textures, the shell, FRIK, the config's Developer and Help-opened writes, and the clock. Kept as small as the controller needs. The controller hands its draw, Restore and Exit handlers to `openPanel`, so the game side never holds the controller. The tests' `RecordingMenuPort` records each call as text and answers each question from a field. |
| **GameMenu** | [src/GameMenu.h](../../src/GameMenu.h) / [.cpp](../../src/GameMenu.cpp) | The port in the game, not unit tested: the ImGui panel in the world and its look from the config, the wrist vrui buttons, the controllers and haptics on the pointing hand, `AdjustInWorld`, the textures (MCM pixels and config spec textures, dropped as the menu closes), `ShellExecute`, FRIK's API and its Papyrus call, `g_config`'s writes. `GameMenu::setup()` has the game's folders. |
| **AdjustInWorld** | [src/AdjustInWorld.h](../../src/AdjustInWorld.h) / [.cpp](../../src/AdjustInWorld.cpp), [src/model/TransformTuning.h](../../src/model/TransformTuning.h) / [.cpp](../../src/model/TransformTuning.cpp) | Tuning a transform with the controllers while the panel is minimized. `TransformTuning` is the game-free maths (unit tested); `AdjustInWorld` reads the controllers, draws the wrist column and sets values in the store for the client to preview. Cancel, a game menu opening, or a client's open/restore request restores the start value. |
| **DevBench** | [src/devbench/MCDevBench.h](../../src/devbench/MCDevBench.h) / [.cpp](../../src/devbench/MCDevBench.cpp) | The mod's devbench tool: menu state and actions (open, select, page, setValue, clientSetValue, save, discard, dialog answers, search, …) and events (menu, Save/Discard, native client calls, MCM events). Add an action here and its e2e test for each new driveable feature. A row, a button and a crumb are reported and pressed from the panel's views (`RowView`, `ButtonView`, `Breadcrumbs`) and rows are shown by `isShown` in `PageRows.h`, so devbench keeps no copy of the panel's rules. |

## UI (`src/ui/`, game-free)

Nothing in `src/ui/` touches the game, so the tests draw it. Looks follow the [design system](../design/design-system/README.md) component of the same name.

| Component | Files | Responsibility |
| --- | --- | --- |
| **FullPanel** | [src/ui/FullPanel.h](../../src/ui/FullPanel.h) / [.cpp](../../src/ui/FullPanel.cpp), [src/ui/Selection.h](../../src/ui/Selection.h) | The panel: title bar and breadcrumbs, tree, content (front page, report, mod page, Help), footer. Owns the selection, and says what is shown and pointed to `StoreSession`; feeds the search field's query to `SearchSession` and draws the tree and page from it (`isFiltered` adds Help and the report to the session's filter; `showWhole` focuses the row it returns); asks `UnsavedDialog` before leaving a dirty mod. MCM mods write at once (`writesChangesAtOnce`), so their Save/Discard read Keep/Revert. `replaceMod` swaps in a re-read config spec, dropping its unsaved changes: the mod list puts it in and returns the new places, which the panel remaps its selection, report, Back and the dialog from. |
| **ModList** | [src/ui/ModList.h](../../src/ui/ModList.h) / [.cpp](../../src/ui/ModList.cpp) | Private to the panel: the mods in order of their display names, the category table, choices and minimum, the groups of the tree, and the last read of each live copy. | **SearchSession** | [src/ui/SearchSession.h](../../src/ui/SearchSession.h) / [.cpp](../../src/ui/SearchSession.cpp) | Private to the panel: the query, what it found per mod, and whether the page is filtered or whole after Back. A new mod list resets it through the panel's `reset`. As the first search after a reset starts, every available mod's store gets `readTexts` (no MCM check). It never touches the tree or the page: `update` says whether the query changed, `showWhole` returns the row to focus. Tested through the panel and `FullPanel::search()` (`SearchSessionTests.cpp`). |
| **FrontPage** | [src/ui/FrontPage.h](../../src/ui/FrontPage.h) / [.cpp](../../src/ui/FrontPage.cpp) | Front page: introduction, quick launch rows, notices (restart pending, mods not available). Empty sections are left out. |

| **ConfigSpecReport** | [src/ui/ConfigSpecReport.h](../../src/ui/ConfigSpecReport.h) / [.cpp](../../src/ui/ConfigSpecReport.cpp) | A config spec's report: source file, live copy controls (Reload, Overwrite, Open, Show), errors and warnings; a press on a problem shows its row. |

| **ModPage** | [src/ui/ModPage.h](../../src/ui/ModPage.h) / [.cpp](../../src/ui/ModPage.cpp) | A page's rows: sections, texts, images, every setting control (delegating to the components below), Reset / per-row Discard, marks, focus ring. ## Model (`src/model/`, game-free)

| Component | Files | Responsibility |
| --- | --- | --- |
| **Model** | [src/model/ConfigDefinition.h](../../src/model/ConfigDefinition.h) | The settings model the UI draws: mods, pages, items, settings with storage, conditions, actions, warnings, problems. See [model.md](../design/model.md). |
| **Setting values** | [src/model/SettingValues.h](../../src/model/SettingValues.h) / [.cpp](../../src/model/SettingValues.cpp) | The setting value rules, by setting type: `sameValue`, `canonicalValue`, `valueProblem` (why a value is invalid), `readJsonValue` (a config spec's `default` and an option's set value), `asStoredType` (a value of the game as a stored type, as Papyrus casts it), `isChoice` (a haptic is one), `isTableType` / `keptAsTable`, `isFrameworkType`. A new setting type adds its case here. | **Store** | [src/model/Store.h](../../src/model/Store.h) | The interface the UI asks for every value: read/set, validity, dirty, Save/Discard, defaults, options, client state, actions (`ActionResult`, `notRunnable`), `readAgain`, `showPage`/`showPointed`. A session opens on selecting a mod and closes on leaving it. Its read part, `StoreReader` (value, value by id, dirty, applies, client state, game INI setting), is what the read-only helpers take: conditions, search, text states, unsaved pages, `withPendingChoices`, the row view and `warningOf`, so their test doubles implement only those. |
| **Conditions** | [src/model/Conditions.h](../../src/model/Conditions.h) / [.cpp](../../src/model/Conditions.cpp) | Evaluating conditions. A condition left open by an unavailable value holds (row shown) but does not `surelyHolds` (warning not told). |
| **Search** | [src/model/Search.h](../../src/model/Search.h) / [.cpp](../../src/model/Search.cpp) | `searchMod`: word-prefix, accent- and case-folded matching (CJK: substring); the most specific match wins. `matchRanges` for underlines. A `notSearched` setting isn't matched by its text. |
| **Categories** | [src/model/Categories.h](../../src/model/Categories.h) / [.cpp](../../src/model/Categories.cpp) | The shipped table (`Categories.json`), the player's choices (`Categories.toml`), a mod's category (`categoryOf`: choice, own, table), the grouping of the tree, and the rows of the Categories page with their options. Names match case-insensitively (`categoryKey`). |
| **Option sets** | [src/model/OptionSets.h](../../src/model/OptionSets.h) / [.cpp](../../src/model/OptionSets.cpp) | A choice whose options set other settings (`SetsStorage`): matching an option's value with a setting's (`hasSetValue`, a color's and a transform's on the parts it names) and setting it (`withSetValue`). The config spec store derives the choice's value, dirty state, default and Discard from those settings; the change counts skip it. An option's `alsoSets` are set by a pick and count for dirty state and Discard, but never decide the value. |
| **Choice options** | [src/model/ChoiceOptions.h](../../src/model/ChoiceOptions.h) / [.cpp](../../src/model/ChoiceOptions.cpp) | Options of a mod's choices: own, from its client, or read in the game (`getOptionTexts`). `typedOptionValue` turns a typed text into a value. |
| **Text markup** | [src/model/TextMarkup.h](../../src/model/TextMarkup.h) / [.cpp](../../src/model/TextMarkup.cpp) | MCM-style tags (`<br>`, `<p align>`, `<font>`, `<b>`, `<i>`, `<u>`, entities). Font sizes are MCM menu sizes, scaled by `MARKUP_BODY_SIZE` in `Drawing.cpp`. |
| **Translations** | [src/model/Translations.h](../../src/model/Translations.h) / [.cpp](../../src/model/Translations.cpp), [src/GameTranslations.h](../../src/GameTranslations.h) / [.cpp](../../src/GameTranslations.cpp) | `$` token translation; `loadGameTranslations` copies the game's table once. |
