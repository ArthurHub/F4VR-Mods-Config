# Domain docs

## Before exploring

This repository uses a single-context layout:

- Read GLOSSARY.md at the repository root for domain vocabulary.
- Read relevant architectural decisions under docs/adr/.

If these files do not exist, proceed silently. Domain modeling creates
them lazily when terms or decisions are resolved.

## Use the glossary's vocabulary

Use defined terms in issue titles, proposals, hypotheses, and test names.
For an undefined concept, reconsider whether it matches existing language
or note the gap for domain modeling.

## Surface decision conflicts

If a proposal contradicts an ADR, identify the ADR and explain why the
decision should be reconsidered.
